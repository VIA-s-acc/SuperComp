# СКМиТ-2026, задание 1, вариант 18

Задача Дирихле для уравнения Пуассона −Δu = 1 в квадрате (−1, 1)² без четверти круга
(x−1)² + (y−1)² ≤ 1, u = sin(x + y) на границе. Метод фиктивных областей, метод сопряжённых
градиентов. Условие — `Задача 1 МокинАЮ.pdf`.

## Структура

| Папка | Этап | Срок |
|---|---|---|
| `01_serial` | последовательная программа | вместе с этапом 1 |
| `02_openmp` | **этап 1**: OpenMP, таблица 1, график ускорения, отчёт `report/report.pdf` | 30.10.2026 |
| `03_mpi` | этап 2: двумерное разбиение + MPI, таблица 2 | 27.11.2026 |
| `04_hybrid` | этап 3: MPI + OpenMP, таблица 3, итоговый отчёт | 18.12.2026 |

В каждом этапе:
- в корне папки — текущая рабочая версия (`solver.cpp`, `Makefile`, `job.lsf`);
- `runs/aN/` — попытка N: её код, LSF-задача, вывод Polus (`*.out`, `*.err`) и `README.md`
  (что изменено, что не так, что дальше);
- `results/` — таблицы и графики для сдачи.

Каждая программа печатает одну строку на запуск:
```
RESULT impl=<serial|omp> attempt=N M=.. N=.. P=1 T=<нити> iters=.. time=<с> w00=<w(0,0)>
```

## Подготовка (один раз)

### Mac

```bash
brew install gcc open-mpi
```
- serial собирается системным `g++` (clang), OpenMP — `/opt/homebrew/bin/g++-16` (в Makefile).
- Для таблиц и графиков — Python 3 с `numpy` и `matplotlib`, для отчёта — `xelatex` (MacTeX).

### IBM Polus

В командах ниже `polus` — короткое имя хоста из `~/.ssh/config` (вход по ssh-ключу курса).

На Polus: GCC 4.8.5 (C++11, OpenMP 3.1), процессоры POWER8 (у ядра 8 аппаратных потоков),
планировщик IBM Spectrum LSF.

## Цикл одной попытки

1. **Mac**: изменить `solver.cpp`, собрать и проверить локально:
   ```bash
   cd ~/GITHUB/SuperComp/02_openmp && make && OMP_NUM_THREADS=4 ./solver 80 80
   ```
2. **Mac**: скопировать на Polus (из корня репозитория):
   ```bash
   scp 02_openmp/solver.cpp 02_openmp/job.lsf polus:~/02_openmp/
   ```
   Первый раз — всю папку: `scp -r 02_openmp polus:~/`.
3. **Polus**: собрать и поставить в очередь:
   ```bash
   ssh polus
   cd ~/02_openmp && make -B POLUS=1 && bsub < job.lsf
   ```
   `-B` обязателен: вместе с папкой может приехать бинарник с Mac, и без пересборки
   `make` решит, что собирать нечего.
4. **Polus**: дождаться окончания и посмотреть вывод:
   ```bash
   bjobs                      # PEND — ждёт, RUN — считается; пусто — закончилась
   cat ~/02_openmp/omp.*.out
   ```
5. **Mac** (не на Polus!): забрать вывод в папку попытки:
   ```bash
   mkdir -p 02_openmp/runs/a4 && scp 'polus:~/02_openmp/omp.*' 02_openmp/runs/a4/
   ```
6. Положить в `runs/aN/` копию `solver.cpp`, `job.lsf`, `Makefile`, написать `README.md`,
   закоммитить: `git commit -m "omp attempt 4"`.

## LSF: шпаргалка

| Команда | Что делает |
|---|---|
| `bsub < job.lsf` | поставить задачу в очередь (печатает номер `Job <…>`) |
| `bjobs` | мои незавершённые задачи |
| `bjobs -d` | недавно завершённые |
| `bjobs -l <id>` | подробности, в т. ч. почему задача стоит в `PEND` |
| `bkill <id>` | снять задачу |

Директивы в начале LSF-файла:

| Директива | Смысл |
|---|---|
| `#BSUB -W 00:15` | лимит времени 15 минут |
| `#BSUB -n 1` | один процесс (serial) |
| `#BSUB -R "affinity[core(16)]"` | 16 ядер на одном узле (OpenMP) |
| `#BSUB -x` | узел целиком, без чужих задач — для честных замеров |
| `#BSUB -o name.%J.out` | файл вывода, `%J` — номер задачи |

На frontend (`ssh polus`) — только сборка и секундные проверки, все замеры — через `bsub`.
Лимит: не больше 4 задач в очереди одновременно.

## Этап 0: последовательная программа (`01_serial`)

```bash
cd ~/01_serial && make -B POLUS=1 && bsub < job.lsf
```
`job.lsf` считает сетки 20×20, 40×40, 80×80, 400×600, 800×1200. Попытки — `01_serial/runs/a1…a4`,
итоговая — попытка 4.

## Этап 1: OpenMP (`02_openmp`)

Число нитей задаётся переменной `OMP_NUM_THREADS`, привязка к ядрам — `GOMP_CPU_AFFINITY`
(LSF-файлы делают это сами: каждая нить — на первый аппаратный поток своего ядра).

**Попытки** — `job.lsf`: 80×80 на 1/4/16 нитях и 400×600 на 1–16 нитях.

**Таблица 1** — `table1.lsf`. Нужны собранные `~/01_serial/solver` (serial, база ускорения)
и `~/02_openmp/solver`:
```bash
cd ~/01_serial && make -B POLUS=1
cd ~/02_openmp && make -B POLUS=1 && bsub < table1.lsf
```
Считает на эксклюзивном узле serial 80×80, 400×600, 800×1200, OpenMP 80×80 на 1/4/16 нитях и обе
сетки таблицы на 2/4/8/16/32 нитях, всё дважды. Около 1.5 минут счёта плюс ожидание узла.

Вывод забрать в `02_openmp/runs/table1/` (на Mac):
```bash
scp 'polus:~/02_openmp/table1.*' 02_openmp/runs/table1/
```

**Тесты** (на Mac и на Polus):
```bash
cd 02_openmp && make test            # на Polus: make test POLUS=1
```

**История итераций** — ключи программы: `--history файл` (‖w(k+1) − w(k)‖ и невязка по итерациям),
`--ref дамп` (ошибка относительно эталона), `--exact` (тестовая задача u = sin(x+y)),
`--dump файл` (сохранить решение).

**Таблица, графики и отчёт** (на Mac):
```bash
02_openmp/build_report.sh
```
Скрипт собирает программу, при необходимости считает локально решения на 20×20, 40×40, 80×80,
800×1200 для рисунков (`02_openmp/dumps/`, в git не попадают) и истории итераций, строит из вывода Polus
`results/table1.md`, `results/*.png` и собирает `report/report.pdf`.

Отдельно:
```bash
cd 02_openmp
python3 make_table.py runs/table1/table1.*.out     # таблица 1 + график ускорения
python3 make_figures.py dumps/sol_20x20.bin dumps/sol_40x40.bin dumps/sol_80x80.bin dumps/sol_800x1200.bin
OMP_NUM_THREADS=4 ./solver 800 1200 --dump dumps/sol_800x1200.bin   # дамп решения
```

## Частые ошибки

- `Permission denied (publickey)` при `scp polus:…` — команда запущена на Polus, а не на Mac.
  На Polus нет нашего `~/.ssh/config`, и имя `polus` там означает сам кластер.
- `иощиы: command not found` — `bjobs` в русской раскладке.
- Задача долго в `PEND` с `-x` — ждёт свободный узел целиком, это нормально.
- Проверить, сколько нитей реально получила программа: поле `T=` в строке `RESULT`;
  как они привязаны — строка `GOMP_CPU_AFFINITY=…` перед ней.
